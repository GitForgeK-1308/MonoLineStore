# 🛍️ MonoLine Store

[![CI](https://github.com/GitForgeK-1308/MonoLineStore/actions/workflows/ci.yml/badge.svg)](https://github.com/GitForgeK-1308/MonoLineStore/actions/workflows/ci.yml)

> Современный интернет-магазин на Django с каталогом товаров, полнотекстовым поиском, корзиной и системой заказов.

## 📖 О проекте

**MonoLine Store** — веб-приложение интернет-магазина, разработанное на Django.

Проект реализует полный пользовательский сценарий: от регистрации и поиска товара до добавления товаров в корзину, оформления заказа и получения уведомления по электронной почте.

В проекте используются PostgreSQL, Redis и Celery. Реализованы транзакции при оформлении заказов, контроль остатков товаров, кэширование, полнотекстовый поиск и автоматическое тестирование.

### 🛍️ Каталог товаров

* Категории товаров
* Типы товаров
* Фильтрация по полу
* Фильтрация по категории
* Фильтрация по типу товара

### 🎨 Варианты товаров

Каждый товар может иметь несколько вариантов, отличающихся размером и цветом.

```text
Футболка
├── S / Black  — 10 шт.
├── M / Black  — 7 шт.
├── L / Black  — 4 шт.
└── XL / White — 8 шт.
```

Для предотвращения дублирования вариантов используется ограничение на уровне базы данных.

### 💰 Система скидок

Для товаров поддерживаются:

* базовая цена;
* процент скидки;
* автоматически рассчитываемая цена со скидкой;
* контроль допустимых значений цены и скидки.

Денежные расчёты выполняются с использованием `Decimal`.

### 🔎 Полнотекстовый поиск

Поиск товаров реализован средствами **PostgreSQL Full-Text Search**.

Используются:

* `SearchVector`;
* `SearchQuery`;
* `SearchRank`;
* веса поисковых полей.

Название товара имеет больший вес при ранжировании результатов, чем описание.

Это позволяет получать результаты, отсортированные по релевантности, а не только по факту совпадения текста.

### ⚡ Кэширование

Для кэширования используется **Redis**.

Кэшируются часто запрашиваемые данные каталога, в частности категории товаров.

Предусмотрена инвалидизация кэша при изменении соответствующих данных.

### 👁️ Недавно просмотренные товары

История последних просмотренных товаров хранится в Django Session.

Количество сохраняемых товаров ограничено, поэтому история не разрастается бесконечно.

## 🛒 Корзина

Корзина реализована на основе пользовательской сессии.

Поддерживаются:

* добавление товара;
* изменение количества;
* удаление товара;
* очистка корзины;
* получение количества товаров;
* проверка доступного остатка.

Основная логика корзины вынесена в отдельный сервис `SessionCart`, что позволяет отделить бизнес-логику от представлений.

---

## 📦 Оформление заказа

При оформлении заказа выполняется последовательность операций:

```text
Корзина
   ↓
Проверка товаров
   ↓
Блокировка вариантов товара
   ↓
Проверка остатков
   ↓
Расчёт стоимости
   ↓
Создание заказа
   ↓
Создание позиций заказа
   ↓
Уменьшение остатков
   ↓
Фиксация транзакции
   ↓
Отправка уведомления
```

Операции оформления заказа выполняются внутри атомарной транзакции.

Для предотвращения проблем с конкурентными заказами используется блокировка строк базы данных через `select_for_update()`.

---

## 🔄 Жизненный цикл заказа

Заказ имеет контролируемую систему статусов:

```text
NEW
 │
 ├──────────────→ CANCELLED
 │
 ↓
PROCESSING
 │
 ├──────────────→ CANCELLED
 │
 ↓
COMPLETED
```

Недопустимые переходы между статусами запрещены бизнес-логикой приложения.

При отмене заказа остатки товаров восстанавливаются.

---

## 📋 История заказа

Позиции заказа сохраняют информацию о товаре на момент покупки:

* название;
* slug;
* цвет;
* размер;
* цена;
* количество.

Таким образом, последующее изменение товара в каталоге не изменяет исторические данные уже созданного заказа.

---

## 📧 Асинхронные задачи

Для выполнения фоновых операций используется **Celery**.

Celery применяется для отправки email-уведомлений без блокировки пользовательского запроса.

Используется схема:

```text
Создание заказа
      ↓
Успешный commit транзакции
      ↓
Celery task
      ↓
Отправка email
```

Для задач предусмотрен механизм повторных попыток при временных ошибках.

## ⚙️ Установка и запуск

### 1. Клонирование репозитория

```bash
git clone https://github.com/GitForgeK-1308/MonoLineStore.git
cd MonoLineStore
```

### 2. Установка зависимостей

Проект использует `uv`:

```bash
uv sync
```

Активировать виртуальное окружение:

```bash
source .venv/bin/activate
```

Для Windows:

```powershell
.venv\Scripts\activate
```

### 3. Настройка переменных окружения

Создайте `.env` на основе:

```text
.env.example
```

Заполните необходимые переменные окружения для:

* Django;
* PostgreSQL;
* Redis;
* Celery;
* email.

> Файл `.env` не должен добавляться в Git.

### 4. Применение миграций

```bash
python manage.py migrate
```

### 5. Создание суперпользователя

```bash
python manage.py createsuperuser
```

### 6. Сбор статических файлов

```bash
python manage.py collectstatic
```

### 7. Запуск приложения

Для разработки:

```bash
python manage.py runserver
```

После запуска приложение будет доступно по адресу:

```text
http://127.0.0.1:8000/
```

## 🔐 Безопасность

Проект использует переменные окружения для хранения конфигурации.

Секретные значения не хранятся непосредственно в исходном коде.

Для production рекомендуется:

* отключать `DEBUG`;
* использовать HTTPS;
* задавать безопасный `SECRET_KEY`;
* ограничивать `ALLOWED_HOSTS`;
* использовать отдельные credentials для базы данных;
* не публиковать `.env`.
